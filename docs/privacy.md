# PRAVAAH — Privacy Documentation

## Principle

> PRAVAAH does not need to know who you are to help you move better through the city.

---

## What PRAVAAH Uses

| Data | Purpose | Granularity |
|---|---|---|
| Zone crowd pressure | Crowd-aware guidance | Zone (neighbourhood) |
| Network segment state | Route/transit status | Route segment |
| Multi-horizon forecasts | Visit planning | Zone × time horizon |
| Approximate neighbourhood (optional) | Nearby recommendations | Zone only |

---

## What PRAVAAH Does Not Collect

- Names, email addresses, phone numbers, or any identity credentials
- Individual movement history or personal trajectories
- Precise GPS coordinates
- Device identifiers or persistent user profiles
- Biometric data of any kind

---

## Aggregation

All crowd data is expressed at the **zone level**, not the individual level.

Visitor crowd counts are translated to labels: `LOW / MODERATE / HIGH / CRITICAL`.
Raw pressure values (e.g. `73.82`) are never exposed in public API responses.

---

## K-Anonymity Suppression

Groups of fewer than **K=10 visitors** are suppressed in all aggregated outputs.
Suppressed values return `{ "visible": false }` rather than an exact count.

This reduces the risk of exposing individual-level information even through aggregated data.

---

## Synthetic Data Disclosure

This prototype uses **synthetic visitor data** generated by the PRAVAAH deterministic simulation engine (`DEMO_SEED=20260908`).

Visitor movements in this prototype are not sourced from real individuals.

Every public API response carries a `data_label` field: `"SIMULATED · AGGREGATED"`.

---

## Optional Location

Approximate location is:
- **OFF by default**. All features work without location via manual destination selection.
- If toggled ON: uses neighbourhood/zone-level area only — never a precise coordinate.
- Location consent state is **session-scoped only** — it is never persisted.
- Revoking location stops location-dependent features immediately.

---

## Retention

| Data Type | Retention |
|---|---|
| Raw event telemetry | 30 minutes (session) |
| Aggregated zone pressure | 6 hours |
| Visitor session state | 60 minutes |
| Operator audit log | Session / in-memory (max 100 events) |
| Individual location | Not persisted |

---

## Operator / Visitor Data Boundary

The visitor-facing API (`/api/visitor/*`) is completely separate from operator APIs.

Visitor responses never contain:
- `dosage_pct` (operator intervention parameters)
- `edge_id`, `candidate_score`, `feature_vector` (internal model data)
- `intervention_score`, `audit_decision` (operator-only decisions)
- Raw pressure floats (translated to crowd-level labels)

This boundary is enforced in backend services, not by CSS hiding.

---

## Privacy Principles

1. **Data Minimization** — collect only what is required for the feature.
2. **Aggregation** — expose zone-level conditions, never individual traces.
3. **Purpose Limitation** — do not reuse crowd data for individual profiling.
4. **Retention Limitation** — visitor session data is not persisted beyond the session.
5. **Transparency** — data sources and synthetic labelling are clearly disclosed.
6. **Optional Participation** — approximate location is never required.
7. **No Individual Surveillance** — individual movement is not tracked or exposed.

---

## Prototype Disclaimer

PRAVAAH is a privacy-aware prototype designed around data minimisation and aggregation principles.

It has not been formally assessed for legal compliance with DPDP, GDPR, or any other privacy framework.

Physical deployment would require independent privacy assessment, legal review, and integration with real consent management infrastructure.
